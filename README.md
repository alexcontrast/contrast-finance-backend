# Contrast Finance v0.5.78

Текущий тестовый этап вкладки «Бухгалтерия» для заявок `Самозанятый`.

## Что работает

- В бухгалтерию автоматически попадают только **активные** заявки `Самозанятый` выбранного месяца. Отменённые/отклонённые заявки и заявки отменённых мероприятий туда не попадают.
- Несколько заявок одного самозанятого можно отметить и **объединить в один чек**. В строке группы показывается общая сумма и расшифровка входящих заявок.
- Один чек e-Salyq Business (JPG/PNG/WEBP/PDF до 10 МБ) хранится на всю группу; его сумма сравнивается с общей суммой выбранных заявок.
- Backend не позволяет объединять заявки разных самозанятых (проверка ИИН, fallback по ФИО) и не позволяет одной заявке находиться в двух группах.
- До загрузки чека группу можно разъединить. После загрузки/распознавания бухгалтерских данных состав защищён от случайного разрушения.
- Для изображений остаётся тестовое локальное QR/OCR-распознавание ФИО, ИИН, номера/даты чека, услуги и суммы с ручной проверкой.
- Оригиналы чеков на MVP хранятся в PostgreSQL.
- Поле будущего АВР уже зарезервировано, но генерация Р-1 и SIGEX/eGov пока не включены.

## Миграция

Новая миграция: `0015_self_employed_groups`. Она создаёт таблицу связей между бухгалтерской группой и заявками и автоматически переносит существующие записи из `0014` как группы из одной заявки. Существующие чеки и распознанные данные не удаляются. Короткий идентификатор укладывается в стандартный `VARCHAR(32)` служебной таблицы Alembic.

`scripts/start.sh` уже выполняет `alembic upgrade head`, поэтому при redeploy Railway применит `0015` автоматически.

## Деплой

После неудачного запуска `v0.5-2.77` развернуть `v0.5-2.78_CHANGED_ONLY.zip` поверх файлов `v0.5-2.77` либо использовать полную сборку `v0.5-2.78_FULL.zip`. База осталась на `0014`, поэтому ручные SQL-команды не нужны.
