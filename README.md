# Contrast Finance v0.5.121

Обновление поверх `v0.5.120`: в заголовке предпросмотра WhatsApp для АВР теперь показываются фамилия и имя самозанятого, чтобы одинаковые фамилии не создавали путаницу. Остальная логика АВР и подписания не менялась.


## v0.5.121 — фамилия + имя в WhatsApp preview АВР

- Заголовок `/sign/avr/{token}` теперь использует первые два компонента сохранённого ФИО: `АВР Contrast-Фамилия Имя на сумму 150 000 ₸ от 03.09.2026`.
- Отчество в заголовок не добавляется. Если в ФИО доступен только один компонент, используется он; если ФИО пустое — `Самозанятый`.
- Сумма, дата, Open Graph, постоянный токен, SIGEX/eGov, DDC и процесс подписания не менялись.
- Backend/browser: `0.5.121`. Миграция БД не требуется.

## v0.5.120 — WhatsApp preview АВР

- Для `/sign/avr/{token}` заголовок страницы и `og:title` формируются сервером по шаблону `АВР Contrast-Фамилия на сумму 150 000 ₸ от 03.09.2026`.
- Фамилия берётся из сохранённого ФИО самозанятого; сумма — из `receipt_amount`; дата — из `act_date` (fallback на дату чека).
- Данные экранируются перед вставкой в HTML; постоянный токен, SIGEX/eGov, DDC и процесс подписания не менялись.
- Устаревшие release-инструкции v0.5.118 в служебных файлах заменены актуальной проверкой v0.5.120.
- Релизный ZIP содержит ровно одну корневую папку `v0.5-2.120/`, без `__MACOSX`.
- Backend/browser: `0.5.120`. Миграция БД не требуется.

## v0.5.119 — формирование АВР без автооткрытия

- После `Сформировать АВР` выполняется только `POST` генерации и точечное обновление строки.
- `window.open`/автоматический вызов просмотра АВР после генерации удалён.
- Сформированный АВР остаётся доступен для ручного открытия из строки бухгалтерии.
- Полная перезагрузка бухгалтерии не выполняется.
- Backend/browser: `0.5.119`. Миграция БД не требуется.

Обновление поверх `v0.5.117`: для чеков Kaspi, где есть ИИН, но отсутствует ФИО самозанятого, добавлено автоматическое восстановление ФИО. Сначала используется собственная история Contrast Finance, затем — best-effort поиск по фиксированным публичным казахстанским сервисам. Все изменения бухгалтерии, Р-1, SIGEX/eGov и live-подписей из `v0.5.117` сохранены.

## v0.5.118 — ФИО по ИИН для чеков Kaspi

- Если в чеке есть ИИН, но нет ФИО, сначала используется собственная история Contrast Finance: ранее подтверждённые/сохранённые чеки с тем же ИИН и сохранённые контакты.
- Если локального ФИО нет, backend делает best-effort поиск ИИН только на фиксированных публичных казахстанских сервисах `ba.prg.kz` и `pk.adata.kz`. Произвольные URL не используются.
- Во внешний сервис передаётся только 12-значный ИИН; изображение чека, сумма, услуга и другие бухгалтерские данные не отправляются.
- Найденное ФИО сохраняется в текущей бухгалтерской строке и дальше становится локальной историей для этого ИИН.
- Внешнее ФИО остаётся обычным редактируемым полем: перед Р-1 его можно исправить вручную. Если публичные источники ничего не нашли, поле остаётся пустым.
- Казахские символы в найденном ФИО сохраняются без транслитерации.
- Миграция БД не требуется. Backend/browser: `0.5.118`.


## Бухгалтерия: только чеки → АВР → подписи

- Заявки самозанятых больше не создают и не занимают строки во вкладке «Бухгалтерия». Они остаются в обычных вкладках «Заявки»/«Архив заявок».
- Пакетная загрузка всегда создаёт самостоятельные строки чеков и больше не пытается автоматически привязывать их к заявкам.
- Старые связи чек ↔ заявка физически не удаляются из БД: они сохраняются как исторические связи для уже существующих документов, но в бухгалтерском UI не показываются.
- Реестр строится только из реально загруженных чеков.
- Фильтр статусов: `Все`, `Без Акта`, `Не подписано ИП`, `Не подписано СЗ`.
- `Без Акта` — чек, по которому Р-1 ещё не сформирован.
- `Не подписано ИП` — АВР существует, но подпись заказчика ИП ещё не получена.
- `Не подписано СЗ` — АВР существует, но подпись самозанятого ещё не получена.

## Бухгалтерия без перезагрузок

- Редактирование реквизитов чека обновляет только текущую строку.
- Формирование АВР, изменение статусов подписей, повторное чтение QR и удаление чека не перерисовывают всю вкладку.
- Массовое «Обновить» блокирует/обновляет строки по одной; строка может автоматически исчезнуть из текущего месяца, если после исправления даты относится к другому месяцу.
- Фоновая проверка каждые несколько секунд запрашивает каждую строку с АВР, пока хотя бы одна сторона не подписала документ. Она не зависит от локального статуса `sent/signing`, поэтому подпись, поставленная на другом устройстве или публичной странице, автоматически перекрашивает `ИП`/`СЗ` в зелёный. Обновляется только конкретная строка.
- Окно пакетной загрузки открывается и обновляется поверх текущей страницы, не пересоздавая бухгалтерскую таблицу.


## iPhone: системный запуск eGov Mobile

- На iPhone основная кнопка ведёт на `/sign/avr/{token}/ios-open`, а не напрямую на `m.egov.kz`.
- Recovery-страница содержит официальный Apple Smart App Banner для текущего приложения eGov Mobile (`app-id=1476128386`).
- В `app-argument` передаётся **ровно тот** `eGovMobileLaunchLink`, который вернул SIGEX для текущей сессии.
- Пользователь нажимает системную кнопку `OPEN / Открыть` в верхнем баннере Safari. Если eGov Mobile установлен, iOS открывает установленное приложение через собственный механизм Smart App Banner.
- Официальный HTTPS deeplink SIGEX оставлен вторичной кнопкой для устройств, где Universal Links работают нормально.
- QR текущей сессии остаётся на той же recovery-странице как резерв для второго устройства.
- Никаких `mobileSign:` в Safari нет; текущая сессия не пересоздаётся и не теряется при неудачном переходе.

## Бухгалтерия самозанятых

- Юридическим источником месяца считается только дата, напечатанная в чеке или полученная из официального QR.
- Если QR не содержит дату, браузер отдельно читает обычную и расширенную шапку чека; для макета Kaspi дополнительно проверяется средняя зона со строкой `Дата и время по Астане`.
- Backend повторно извлекает дату из сохранённого OCR-текста и исправляет типичные подмены `O/О → 0`, `I/І/l → 1`, а также время с точкой вместо двоеточия.
- Учтены реальные варианты e-Salyq `августа → aprycta / aBrycta` и суффикс года `г. → r.`. Исправление применяется только внутри полной конструкции даты и не подставляет месяц наугад.
- Если старый QR не содержит даты, а Tesseract.js в браузере не загрузился или оборвал визуальный проход, backend запускает локальный Tesseract для сохранённого JPG/PNG/WEBP и сохраняет найденную дату вместе с OCR-доказательством.
- Чек без даты не попадает в месяц события/загрузки. Он показывается отдельной предупреждённой строкой `Дата не распознана` до исправления.
- Поддерживаются русские и казахские названия месяцев, даты без времени, DMY/YMD, ISO, Unix и структурированные даты KGD.
- OCR запускается с `kaz+rus+eng` и сохраняет буквы `Ә Ғ Қ Ң Ө Ұ Ү Һ І`; при недоступности модели используется `rus+eng`.
- Более точное казахское ФИО имеет приоритет над испорченным OCR-вариантом.
- Пропущенный ИИН безопасно восстанавливается по другим чекам того же ФИО только при одном однозначном совпадении. По ИИН также восстанавливается лучшее полное ФИО.
- Восстановление выполняется не только при загрузке нового чека: старые строки проверяются при открытии бухгалтерии, а также перед формированием АВР.
- Если одно полное ФИО встречается с двумя разными ИИН, автоматическая подстановка блокируется.
- Номер e-Salyq/Kaspi строго 12-значный. Ошибка `2000000000033` нормализуется в `000000000033`.
- Добавлены официальные QR Kaspi `receipt.kaspi.kz/web/self-employed`: сервер получает структурированную карточку и точно читает дату, ИИН, номер, сумму и наименование.
- АВР нельзя сформировать без даты чека, ФИО, ИИН, номера, суммы и наименования.

## Координатор и ЗП менеджера

- Доступны `Нал`, `На карту`, `Самозанятый`.
- Для `Самозанятый` фамилия обязательна.
- Способ сохраняется в конкретной заявке, но никогда не закрепляется за позицией.
- НДС и вычеты по этим двум типам всегда равны нулю независимо от способа оплаты.
- То же правило применяется в Telegram-боте.

## Установка

Патч `v0.5-2.121_CHANGED_ONLY.zip` содержит только изменённые файлы относительно `v0.5.120` с путями от корня проекта. Распакуйте его поверх текущей `v0.5.120` с заменой файлов.

После деплоя:

1. Проверьте `/api/status` — версия должна быть `0.5.121`.
2. Отправьте в WhatsApp новую/ещё не кэшированную ссылку АВР: в карточке предпросмотра должен появиться заголовок вида `АВР Contrast-Иванов Иван на сумму 150 000 ₸ от 03.09.2026`.
3. Откройте эту ссылку и убедитесь, что обычная страница подписания АВР загружается как раньше.
4. На iPhone нажмите `Открыть eGov Mobile` — откроется служебная страница Contrast, а не App Store.
5. В верхнем системном Smart App Banner eGov Mobile нажмите `OPEN / Открыть`. Если баннер был ранее скрыт или eGov не принял контекст, на этой же странице доступны официальный deeplink и QR текущей сессии; АВР пересоздавать не нужно.

WhatsApp может некоторое время хранить старый preview уже отправленного URL. Для проверки сразу после деплоя используйте новую ссылку АВР; сама серверная страница всегда отдаёт актуальный динамический заголовок.

Все исправления чеков, казахских ФИО, ИИН, Р-1, DDC, постоянных ссылок АВР, iPhone/SIGEX/eGov и live-статусов подписей из `v0.5.117` сохранены.

Новой миграции БД нет. Единственная Alembic-вершина: `0021_avr_signed_ddc`.
