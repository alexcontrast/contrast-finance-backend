# Contrast Finance v0.5.57

Точечный backend-патч восстановления БИН/ИИН, НДС и налоговых вычетов у позиций с уже созданными заявками «По счету».

## Причина

- После успешной проверки КГД данные сохранялись в позиции и копировались в снапшот заявки.
- Обычный `PATCH` позиции не защищал уже закреплённый налоговый контекст.
- Старое автосохранение, локальный черновик или вторая вкладка могли позже отправить устаревшую строку и затереть в позиции БИН, статус КГД, НДС и вычеты нулями.
- Фронтенд блокировал такое редактирование, но backend не обеспечивал это правило.

## Исправлено

- Создание заявки, проверка КГД и сохранение позиции сериализованы блокировкой строки в PostgreSQL.
- Неполный устаревший `PATCH` больше не очищает подтверждённый налоговый контекст.
- Если по позиции уже есть активная заявка «По счету», backend восстанавливает контекст из её снапшота.
- Миграция при деплое восстанавливает существующие пропуски из:
  1. журнала успешной проверки КГД;
  2. данных контрагента;
  3. налогового снапшота заявки;
  4. сохранённой суммы/налогового статуса, если исчезли только рассчитанные суммы.
- Уже заполненные ненулевые НДС и вычеты, включая ручные значения администратора, не перезаписываются.

## Деплой

Обычный деплой. `scripts/start.sh` автоматически применит миграцию `0012_invoice_tax_repair`.

Ручная чистка позиций не нужна. Если у конкретной заявки не сохранилось вообще ни БИН, ни связи с контрагентом, ни записи успешной проверки КГД, восстановить её автоматически не из чего — такую позицию администратор должен один раз проверить повторно.
