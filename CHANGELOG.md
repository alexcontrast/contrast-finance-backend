# Contrast Finance — история изменений

## v0.5.65 — восстановление модуля закрытия месяца

- Исправлен второй разрыв комплекта `v0.5.63–v0.5.64`: маршрут бонусов импортировал `calculate_closing` и `apply_calculated_to_closing`, но актуальный `monthly_closings.py` не был включён в патчи.
- В патч включена проверенная совместимая пара `manager_bonuses.py` + `monthly_closings.py`.
- Пересчёт уже закрытого месяца после выплаты бонуса сохранён: расход относится к месяцу бонуса, а итоги закрытия обновляются без повторной выплаты.
- Бонусы, годовая статистика, Google Sheets, автосохранение и сброс PIN не изменялись.
- Новых миграций нет; `0013_manager_bonus` остаётся текущей.

## v0.5.64 — восстановление запуска после v0.5.63

- Исправлен разрыв между маршрутом Google Sheets и сервисом годовой статистики: публичная функция `build_year_statistics_sections` снова присутствует в сервисе.
- Маршрут и сервис включены в один патч и используют одно имя функции, поэтому импорт `app.main` больше не падает при запуске контейнера.
- Расчёт и выплата бонусов `v0.5.63`, включая добавление бонуса в «ЗП» менеджера годовой статистики, сохранены без изменений.
- Миграция `0013_manager_bonus` не повторяется: уже применённая миграция остаётся текущей.

## v0.5.63 — выплата месячного бонуса менеджеру

- Во вкладке администратора «Обзор» рядом со сменой PIN и удалением менеджера добавлена круглая кнопка 💰 «Выплатить бонус».
- До выполнения личного плана выбранного месяца кнопка неактивна; после выполнения открывает компактное подтверждение с доходом менеджера, ставкой 5% и точной суммой выплаты.
- База бонуса совпадает с фактом личного плана: `final_company_income` по мероприятиям менеджера с учётом долей соавторов.
- После подтверждения бонус сохраняется специальным защищённым расходом именно выбранного месяца и целиком относится на отдел менеджера — «Санжар» или «Рауфаль».
- На одного менеджера за один месяц можно создать только одну выплату; повторный запрос безопасно возвращает уже созданный бонус.
- Выплаченный бонус включается в строку «ЗП» менеджера в общей годовой статистике по соответствующему месяцу и в годовой итог.
- Если бонус выплачен после закрытия месяца, сохранённые итоги закрытия пересчитываются с новым расходом.
- В списке расходов бонус помечен отдельно и защищён от ручного изменения или удаления.

Добавлена миграция `0013_manager_bonus`: служебные поля бонуса в `monthly_expenses` и уникальная защита одной выплаты на менеджера за месяц.

## v0.5.62 — защита новой позиции от двойного сохранения

- Устранена гонка между автосохранением и ручной кнопкой «Сохранить черновик»: параллельные сохранения одной строки теперь объединяются в одну последовательную операцию.
- Пока новая временная строка создаётся на сервере, повторное сохранение ждёт тот же запрос и больше не отправляет второй `POST`.
- Каждая явно добавленная строка получает стабильный ключ создания, который сохраняется вместе с локальной резервной копией черновика.
- Backend использует этот ключ идемпотентно: повторный запрос после обрыва связи, задержки ответа или восстановления вкладки возвращает уже созданную позицию вместо создания дубля.
- Две намеренно одинаковые строки, отдельно добавленные менеджером, не объединяются — у каждой свой ключ создания.
- Защита работает также для новой позиции, создаваемой из окна заявки на оплату.

Миграция базы данных не требуется: для ключа повторного запроса используется уже существующее уникальное поле позиции.

## v0.5.61 — безопасное автосохранение сметы

- Убрано автоматическое создание новой позиции по `Enter` в последней строке сметы.
- Новая строка сметы теперь появляется только после явного нажатия «Добавить позицию».
- Создание новой позиции из заявки на оплату сохранено без изменений.
- Автосохранение сохранено, но стало версионным: поздний ответ сервера больше не перезаписывает ввод, который менеджер успел изменить во время запроса.
- Если строка изменилась во время сохранения, свежая локальная версия остаётся на экране и автоматически отправляется следующим запросом.
- Перед сменой способа оплаты и другими перерисовками значения строки по-прежнему полностью синхронизируются из формы в черновик.
- Локальная резервная копия ввода в браузере сохранена вместе с ручной кнопкой «Сохранить черновик».
- Полностью пустая временная строка не отправляется на сервер, а backend дополнительно отклоняет такой запрос из старой вкладки или кеша.

Миграция базы данных не требуется.

## v0.5.60 — сброс PIN менеджера администратором

- Во вкладке администратора «Обзор» рядом с удалением активного менеджера появилась круглая кнопка с замком для восстановления доступа.
- По нажатию администратор открывает компактное окно, задаёт или генерирует новый PIN и может скопировать его для менеджера.
- Старый PIN не раскрывается: он хранится только как необратимый хеш.
- Исправлена смена PIN у пользователей, перенесённых из старой системы: после сброса вход гарантированно переключается на новый PIN.
- Backend и интерфейс проверяют, что PIN содержит от 4 до 12 цифр.

Миграции базы данных не требуются.

## v0.5.59 — одинаковые 5% в карточках менеджера и админа

- Поле `taxes_net`, уже рассчитанное единым калькулятором, добавлено в API-схему сводки мероприятия.
- Обычный endpoint сводки и оптимизированные bundle-ответы менеджера/админки теперь передают это поле в интерфейс.
- Админская карточка мероприятия на «Упрощёнке» показывает полные 5% от оборота без уменьшения на вычеты — то же значение, что и кабинет менеджера.
- Запасная frontend-формула для старого ответа API также учитывает режим: вычеты уменьшают налог только при ОУР.
- Итоговая месячная агрегация налогов ИП Contrast Event не изменялась: она по-прежнему собирает вычеты со всех мероприятий отдельно.

Миграции базы данных не требуются.

## v0.5.58 — налог 5% для Упрощёнки

- Найдена точная причина заниженной суммы в графе «Налоги 5% к уплате»: единое поле `taxes_net` безусловно вычитало вычеты подрядчиков из рассчитанного налога для всех режимов.
- Для режима «Упрощёнка» `taxes_net` теперь всегда равен полным 5% от оборота без уменьшения на вычеты.
- Для ОУР прежняя логика сохранена: налог к уплате уменьшается на доступные налоговые вычеты.
- Та же развилка добавлена в локальный предпросмотр черновика, поэтому до и после сохранения менеджер видит одинаковую сумму.
- Google Sheets export автоматически получает исправленное значение из единого расчётного поля.

Миграции базы данных не требуются. НДС, доход компании, зарплата менеджера, клиентская надбавка «Банк+налоги» и налоговые снапшоты заявок не менялись.
